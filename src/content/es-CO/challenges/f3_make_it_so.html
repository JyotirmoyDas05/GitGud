Crea un pequeño árbol de carpetas desde la terminal con mkdir y touch.

Crear cosas

Todo hasta ahora ha sido de solo lectura — mirar y moverse. Dos comandos cubren casi todo lo de crear:

  • mkdir — make directory. Crea una carpeta.
  • touch — crea un archivo vacío.

Ambos crean cosas dentro del directorio donde estás ubicado, a menos que les des una ruta que diga lo contrario. Aquí es donde el reto anterior da sus frutos: si no tienes claro dónde va a aparecer una carpeta nueva, ejecuta pwd primero.

touch tiene un nombre raro porque crear archivos es su trabajo secundario — su propósito real es actualizar la fecha de un archivo, y crear uno que aún no existe fue un accidente conveniente. Todo el mundo lo usa por el accidente.

Crea la carpeta de práctica

Empieza desde casa, para que no haya dudas de dónde aparece esto:

cd ~

Ahora crea una carpeta y entra en ella:

mkdir gitgud-practice cd gitgud-practice

Como cd, mkdir no dice nada cuando funciona. Compruébalo con ls si quieres tranquilizarte — deberías hacerlo, las primeras veces.

Nómbrala exactamente gitgud-practice — la comprobación busca ese nombre. Y fíjate en que no tiene ningún espacio. Los espacios en los nombres son legales pero hacen que las rutas sean incómodas de escribir, por eso el mundo de la programación usa guiones.

Crea un archivo

Ahora deberías estar dentro de gitgud-practice. Confírmalo si quieres:

pwd

Luego crea un archivo vacío:

touch hello.txt ls

hello.txt

Existe y está vacío — cero bytes. touch crea el recipiente; poner algo dentro es trabajo de un editor de texto. Ábrelo en el editor que quieras y escribe algo si quieres; nada aquí depende de ello.

Crea una carpeta, y luego un archivo dentro

Todavía en gitgud-practice:

mkdir notes

Ahora — aquí está la parte útil — crea un archivo dentro de notes sin entrar allá, dándole a touch una ruta relativa en lugar de un nombre solo:

touch notes/day-one.txt

Lee ese argumento como lees una ruta: la carpeta notes, y dentro, un archivo llamado day-one.txt. Los comandos aceptan rutas, no solo nombres, en todas partes. Casi nunca tienes que ir con cd a un lado solo para hacerle una cosa.

Revisa tu trabajo:

ls notes

Escribe ls no y presiona Tab. El autocompletado con Tab funciona con las carpetas que acabas de crear, igual que con cualquier otra — y te ahorra el error que si no te tendría mirando «No such file or directory» un rato.

Varias carpetas a la vez

Intenta crear una carpeta anidada de la forma obvia y mira cómo se niega:

mkdir notes/archive/2026

mkdir: cannot create directory 'notes/archive/2026': No such file or directory

Lógico — archive aún no existe, y mkdir crea un directorio, no una cadena de ellos. En lugar de crear cada nivel a mano, pídeselo:

mkdir -p notes/archive/2026 ls notes

-p es la forma corta de parents: crea las carpetas que falten por el camino. Esta es esa regla de hace dos retos en acción — mismo comando, una opción, distinto comportamiento, y mkdir --help te lo habría contado.

Tu árbol ahora se ve así:

gitgud-practice/ ├── hello.txt └── notes/ ├── day-one.txt └── archive/ └── 2026/

Qué se revisa

Dos cosas, juntas. Git Gud lee la carpeta gitgud-practice para confirmar que el árbol está realmente ahí, y revisa tu historial del shell buscando mkdir y touch — porque cualquiera puede hacer clic derecho y elegir Nueva carpeta, y no es de eso de lo que trata este módulo.

Usa Select directory aquí abajo para elegir tu carpeta gitgud-practice, cierra la terminal con exit para que se guarde tu historial, y presiona Verificar.

Quédate con la carpeta cuando termines, o bórrala — nada posterior depende de ella. Crearás una carpeta de proyecto real muy pronto, con los mismos dos comandos.

Crear cosas

  • Crear una carpeta
    • mkdir <FOLDERNAME>
  • Crear una cadena entera de carpetas
    • mkdir -p <A>/<B>/<C>
  • Crear un archivo vacío
    • touch <FILENAME>
  • Crear uno dentro de otra carpeta
    • touch <FOLDERNAME>/<FILENAME>
  • Revisar que funcionó
    • ls <FOLDERNAME>

Ese es todo el módulo de terminal. Ya puedes abrir una terminal, leer un prompt, ejecutar un comando con opciones y argumentos, averiguar dónde estás, ir a otro lado, y crear cosas una vez allá. Todo lo que Git te pida desde aquí son esos mismos movimientos con distintas palabras.
