用 mkdir 和 touch 從終端機蓋一棵小小的資料夾樹。

創造東西

到目前為止都是唯讀——看看、走走。創造的部分兩個指令幾乎全包了：

  • mkdir — make directory 的意思。建立資料夾。
  • touch — 建立空檔案。

兩個都是在你目前站的目錄裡面創造，除非你給的路徑另有說明。這就是上個挑戰回本的地方：不確定新資料夾會落在哪裡，先執行 pwd。

touch 名字很怪，因為建檔案只是它的副業——它的本業是更新檔案的時間戳記，順手建出還不存在的檔案只是附帶的意外。大家都是為了這個意外在用它。

建立練習資料夾

從家開始，就不會對落點有疑問：

cd ~

建立資料夾並走進去：

mkdir gitgud-practice cd gitgud-practice

跟 cd 一樣，mkdir 成功時什麼都不說。想要安心就用 ls 確認——前幾次應該這樣。

名字一定要叫 gitgud-practice——檢查找的就是這個名字。也注意裡面沒有空白。名字有空白是合法的，但路徑會很難打，所以程式設計的世界愛用連字號。

建立檔案

你現在應該在 gitgud-practice 裡面。想確認就確認：

pwd

再建立一個空檔案：

touch hello.txt ls

hello.txt

它存在，而且是空的——零位元組。touch 造的是容器；裝東西進去是文字編輯器的工作。想打點什麼就用順手的編輯器打開來打；這裡不依賴它。

建資料夾，再在裡面建檔案

還在 gitgud-practice 裡：

mkdir notes

接下來是有用的部分——在 notes 裡面 不走進去，直接建檔案，給 touch 一條相對路徑而不是光禿禿的名字：

touch notes/day-one.txt

把那個引數當路徑來讀：資料夾 notes 裡面，一個叫 day-one.txt 的檔案。指令到處都吃路徑，不只吃名字。你幾乎永遠不必為了對某處做一件事就 cd 過去。

檢查你的成果：

ls notes

輸入 ls no 再按 Tab。Tab 補全對剛建好的資料夾一樣管用——還能救你免於打錯字，不然你會盯著 "No such file or directory" 發呆一分鐘。

一次建好幾層

試著用直覺的方法建巢狀資料夾，看它拒絕你：

mkdir notes/archive/2026

mkdir: cannot create directory 'notes/archive/2026': No such file or directory

很合理——archive 還不存在，而 mkdir 一次只建一個目錄，不是建一整串。與其一層一層手動建，叫它一次建完：

mkdir -p notes/archive/2026 ls notes

-p 是 parents 的縮寫：順手把路上缺的資料夾都建起來。這就是兩關前的規則在發威——同樣的指令、一個選項、行為不同，而 mkdir --help 本來就會告訴你。

你的樹現在長這樣：

gitgud-practice/ ├── hello.txt └── notes/ ├── day-one.txt └── archive/ └── 2026/

檢查什麼

兩件事一起查。Git Gud 讀 gitgud-practice 資料夾確認樹真的在，並且檢查你的殼層歷史裡有 mkdir 和 touch——因為右鍵新增資料夾誰都會，那不是這個模組要教的。

用下面的 Select directory 選你的 gitgud-practice 資料夾，用 exit 關掉終端機存檔，按 Verify。

做完資料夾要留要刪隨你——後面都不依賴它。你很快會用同樣的兩個指令建真正的專案資料夾。

創造東西

  • 建資料夾
    • mkdir <FOLDERNAME>
  • 建一整串資料夾
    • mkdir -p <A>/<B>/<C>
  • 建空檔案
    • touch <FILENAME>
  • 建在另一個資料夾裡面
    • touch <FOLDERNAME>/<FILENAME>
  • 確認成功了
    • ls <FOLDERNAME>

終端機模組到此結束。你會開終端機、讀提示字元、用選項和引數執行指令、查出自己在哪、去別的地方、到了再創造東西。往後 Git 要求的，都是同樣的動作換不同的詞。
