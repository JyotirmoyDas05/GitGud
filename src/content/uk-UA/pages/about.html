Git Gud навчає повсякденних команд Git, якими розробники користуються насправді, разом із GitHub Flow — способом, у який люди співпрацюють на GitHub. Він починається раніше, ніж більшість посібників: перші п'ять завдань присвячені самому терміналу, бо «відкрийте термінал і виконайте git init» — це не одна інструкція, якщо ви ніколи не відкривали термінал.

Деякі завдання потребують підключення до інтернету, тому для їх виконання вам знадобиться бути онлайн. Ви завжди можете відкрити застосунок і читати завдання та ресурси офлайн.

Справжнє середовище розробки

Git Gud використовує справжній термінал, справжній Git і справжній GitHub, а не емулює жоден із них. Коли ви завершите навчання, у вас будуть справжні репозиторії у вашому обліковому записі GitHub і зелені квадратики на графіку внесків. Тут ніщо не є симуляцією, і саме тому кожне завдання перевіряється шляхом запуску Git щодо ваших власних репозиторіїв — якщо завдання зараховано, отже, воно справді спрацювало.

Що вам потрібно

Нічого, для початку — модуль терміналу використовує те, що на вашому комп'ютері вже є. Після цього — Git та обліковий запис GitHub, у створенні яких вам допоможуть два із завдань. Вам не потрібні Node.js, Python чи будь-яке інше середовище виконання — Git Gud постачається як єдиний нативний застосунок.

Про завдання з терміналу

Такі команди, як pwd і ls, нічого не змінюють на вашому комп'ютері, тому немає файлу, який можна було б перевірити опісля, щоб дізнатися, чи ви їх виконували. Ці завдання перевіряються шляхом читання файлу історії, який веде ваша власна оболонка — ~/.bash_history та його відповідники для Zsh, Fish і PowerShell. Читаються лише останні кілька сотень рядків, це відбувається повністю на вашому комп'ютері, нічого нікуди не надсилається, і кожна перевірка називає файл, який вона прочитала.

Як це створено

Git Gud — це застосунок на Tauri: бекенд на Rust, який запускає Git і взаємодіє з GitHub, та інтерфейс на React, що відображається власним вебпереглядачем операційної системи. Тут немає вбудованого рушія браузера, і саме тому завантаження вимірюється мегабайтами, а не сотнями мегабайтів.

Супровідний репозиторій, який ви форкаєте під час виконання завдань, — це git-gud-verifywork. Його автоматизація працює повністю на GitHub Actions — тут немає сервера, який міг би вийти з ладу.

Подяки

Git Gud — це порт застосунку Git-it, застосунку на Electron, написаного @jlord та багатьма дописувачами, випущеного за ліцензією BSD 2-Clause. Структура завдань і значна частина текстів належать їм. Ця версія перебудовує застосунок на Tauri, замінює виведений з експлуатації сервіс перевірки на GitHub Actions і виправляє низку перевірок, які перестали працювати зі змінами Git і GitHub.

Дизайн інтерфейсу запозичує свою систему токенів у T3 Code, використану за ліцензією MIT.
