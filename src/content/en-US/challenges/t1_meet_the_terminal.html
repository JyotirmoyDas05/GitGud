Open a terminal, run your first two commands, and learn to read the line it greets you with.

What a Terminal Is

A terminal is a window where you type instructions to your computer instead of clicking them. That's the whole idea. Everything you already do — open a folder, make a new one, rename a file, copy something — has a typed equivalent, and the typed version is usually faster and always repeatable.

You will hear several words for roughly the same thing, and it's worth untangling them once:

  • The terminal is the window. It draws text and takes your keystrokes.
  • The shell is the program running inside it that actually understands what you type. Common ones are Bash, Zsh and PowerShell.
  • Command line and CLI are general names for this way of working.

In practice people use all four interchangeably, and so will we. If someone tells you to "open a terminal", they mean this window.

It looks intimidating because it's empty and nothing tells you what to do. It isn't dangerous. Nothing in this module can break anything — you'll be printing your own username and making a practice folder. Nobody is judging your typing.

Open Your Terminal

Windows. Windows ships with PowerShell, but the commands in this module — and nearly every tutorial, README and Stack Overflow answer you will ever read — are written for a Unix-style shell. The easiest way to get one is Git Bash, which comes free with Git for Windows. Install it with the default options, then open Git Bash from the Start menu.

That install also puts Git on your computer, which you will need later anyway — a challenge further down confirms it's set up properly. Two birds.

macOS. Press Cmd + Space, type Terminal, press enter. It's also in Applications › Utilities.

Linux. Usually Ctrl + Alt + T, or search your applications for Terminal.

You should now be looking at a mostly empty window with one line of text and a blinking cursor. That line is the next thing to understand.

Reading the Prompt

The line waiting for you is called the prompt. It isn't decoration — it's a status bar, and it's telling you three useful things before you type anything at all.

jyoti@laptop ~/code $

  • jyoti — who you are signed in as.
  • laptop — which machine you're talking to. This matters more than you'd think once you start connecting to other computers.
  • ~/code — where you are. The terminal is always standing in some folder, and this is it. The next challenge but one is entirely about this part.
  • $ — "your turn". Everything after it is what you type.

Yours will look different. Zsh on macOS often ends with % instead of $, some prompts are two lines, some are colourful, some show the current Git branch. The parts move around; the idea doesn't.

This is also why documentation writes commands with a $ in front — it's shorthand for "type this at your prompt". You never type the $ itself. The code boxes in Git Gud show it too, and the copy button leaves it out.

Say Hello

Type this and press enter:

whoami

It prints your username. That's it. That's the whole command.

jyoti

Now try another:

date

Sat Sep 20 09:24:11 IST 2026

You have now used a terminal. The pattern you just met — type a word, press enter, read what comes back — is the entire interaction. Everything else is more interesting words.

Press the up arrow. Your shell remembers what you typed and will hand it back to you. Press it a few times. This is the single biggest time-saver on this page.

Closing the Terminal

Clicking the window's close button works. But there's a proper way, and it's a command like any other:

exit

The window closes. Reopen it the same way you did before — a terminal is a cheap, disposable thing, and you'll open and close dozens a day without thinking about it.

One reason to prefer exit: that memory of what you typed lives in a file, and Bash and Zsh only write it out when the shell closes properly. Which brings us to how this challenge is checked.

How Git Gud Checks This

Commands like whoami don't change anything on your computer, so there's no folder or file for the app to look at afterwards. Instead, Git Gud reads the history file your own shell keeps — ~/.bash_history for Bash, and the equivalent for Zsh, Fish and PowerShell — and looks for the commands this challenge asked for.

It reads the last few hundred lines, on your machine only, and nothing is sent anywhere. Each check below names the exact file it read.

So: run whoami and date, then exit to close the terminal so your shell saves its history, open a fresh one, and come back here and press Verify.

If the Check Can't See Your Commands

Bash and Zsh save their history when the shell exits, not as you type. If you did the work but the check can't find it, your terminal is almost certainly still open. Type exit and press Verify again.

On Windows, cmd.exe keeps no history at all. Use Git Bash or PowerShell.
