Build a small folder tree from the terminal with mkdir and touch.

Making Things

Everything so far has been read-only — looking and moving. Two commands cover almost all of the making:

  • mkdir — make directory. Creates a folder.
  • touch — creates an empty file.

Both create things inside the directory you're currently standing in, unless you give them a path that says otherwise. This is where the last challenge pays off: if you're not sure where a new folder is about to land, run pwd first.

touch has an odd name because creating files is its side job — its actual purpose is updating a file's timestamp, and creating one that doesn't exist yet was a convenient accident. Everyone uses it for the accident.

Make the Practice Folder

Start from home, so there's no doubt about where this lands:

cd ~

Now make a folder and step into it:

mkdir gitgud-practice cd gitgud-practice

Like cd, mkdir says nothing when it works. Check with ls if you want the reassurance — you should, the first few times.

Name it exactly gitgud-practice — the check looks for that name. And notice there's no space in it. Spaces in names are legal but make paths awkward to type, which is why the programming world leans on hyphens.

Make a File

You should now be inside gitgud-practice. Confirm it if you like:

pwd

Then create an empty file:

touch hello.txt ls

hello.txt

It exists and it's empty — zero bytes. touch makes the container; putting something in it is a text editor's job. Open it in whatever editor you like and type something if you want; nothing here depends on it.

Make a Folder, Then a File Inside It

Still in gitgud-practice:

mkdir notes

Now — here's the useful bit — create a file inside notes without going in there, by giving touch a relative path instead of a bare name:

touch notes/day-one.txt

Read that argument the way you read a path: the folder notes, and inside it, a file called day-one.txt. Commands take paths, not just names, everywhere. You almost never have to cd somewhere just to do one thing to it.

Check your work:

ls notes

Type ls no and press Tab. Tab completion works on the folders you just made, same as any other — and it saves you from the typo that would otherwise have you staring at "No such file or directory" for a minute.

Several Folders at Once

Try making a nested folder the obvious way and watch it refuse:

mkdir notes/archive/2026

mkdir: cannot create directory 'notes/archive/2026': No such file or directory

Fair enough — archive doesn't exist yet, and mkdir makes one directory, not a chain of them. Rather than making each level by hand, ask it to:

mkdir -p notes/archive/2026 ls notes

-p is short for parents: make any missing folders along the way. This is that rule from two challenges ago in action — same command, one option, different behaviour, and mkdir --help would have told you about it.

Your tree now looks like this:

gitgud-practice/ ├── hello.txt └── notes/ ├── day-one.txt └── archive/ └── 2026/

What Gets Checked

Two things, together. Git Gud reads the gitgud-practice folder to confirm the tree is really there, and checks your shell history for mkdir and touch — because anyone can right-click and choose New Folder, and that isn't what this module is about.

Use Select directory below to pick your gitgud-practice folder, close the terminal with exit so your history is saved, and press Verify.

Keep the folder when you're done, or delete it — nothing later depends on it. You'll make a real project folder soon enough, with the same two commands.

Making Things

  • Make a folder
    • mkdir <FOLDERNAME>
  • Make a whole chain of folders
    • mkdir -p <A>/<B>/<C>
  • Make an empty file
    • touch <FILENAME>
  • Make one inside another folder
    • touch <FOLDERNAME>/<FILENAME>
  • Check it worked
    • ls <FOLDERNAME>

That's the whole terminal module. You can open a terminal, read a prompt, run a command with options and arguments, find out where you are, go somewhere else, and make things once you're there. Everything Git asks of you from here is those same moves with different words.
