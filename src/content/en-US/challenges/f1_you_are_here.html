Find out where your terminal is standing, see what's around you, and identify your home directory.

The Terminal Is Always Somewhere

Here is the one idea that makes everything else click: your terminal is always inside exactly one folder. Not "open at" it — standing in it, the way a file explorer window is showing one folder at a time.

That folder is called the current directory, or the working directory. Every command you type happens there unless you say otherwise. ls lists that folder. mkdir notes makes the new folder inside it. Later, git init will turn that folder into a repository — which is why "which folder am I in?" stops being a trivia question and becomes the thing you check before you act.

Almost every confusing moment a beginner has with the terminal — "it says the file doesn't exist but I can see it right there" — is this. The file exists. You're standing somewhere else.

Directory Means Folder

Directory and folder are the same thing. "Folder" is what the graphical desktop called it; "directory" is the older name, and it's the one the terminal, the documentation and every command name use — mkdir is make directory, cd is change directory. Expect both words, mean the same thing by them.

Your computer stores two kinds of thing:

  • Files hold content — text, a photo, some code.
  • Directories hold other files and directories. That's all they do.

Directories inside directories inside directories, all the way down from one starting point. That nesting is the filesystem, and it's a tree.

Print Where You Are

Open your terminal. The first command every terminal user learns to trust:

pwd

Short for print working directory. It answers the question with a full address:

/Users/jyoti

On Windows with Git Bash you'll see something like /c/Users/jyoti — same place, Git Bash just writes the C: drive in Unix style.

That address is called a path. Read it left to right as a set of directions: start at the very top, go into Users, then into jyoti. Each / is a step further in. A path that starts from the very top like this is an absolute path — it means the same thing no matter where you happen to be standing when you use it.

pwd is free, instant, and changes nothing. Run it whenever you're unsure. Nobody will ever think less of you for running pwd.

Look Around

Now see what's actually here:

ls

Desktop Documents Downloads Music Pictures

Recognise those? They're the same folders you see in your file explorer, because there is no separate "terminal filesystem" — it's one computer and two ways of looking at it. Open your file explorer next to the terminal and put them side by side once. It makes the whole thing feel less abstract.

To tell files and directories apart at a glance, ask for detail:

ls -l

drwxr-xr-x 5 jyoti staff 160 Sep 20 09:12 Documents -rw-r--r-- 1 jyoti staff 1024 Sep 20 09:14 notes.txt

Ignore almost all of that for now and look at the very first character of each line. A d means directory. A - means an ordinary file. That single letter is the answer.

Home, and the Squiggle

When you open a terminal it doesn't start at a random spot. It starts in your home directory — the folder that belongs to your user account, the one holding your Desktop, Documents and Downloads.

  • macOS: /Users/yourname
  • Linux: /home/yourname
  • Windows: C:\Users\yourname, which Git Bash shows as /c/Users/yourname

You will type it constantly, so it has a shortcut: ~, the tilde. Anywhere a path is expected, ~ means "my home directory". So ~/Documents is your Documents folder, spelled the same way on every machine and by every user — which is exactly why documentation is full of tildes.

Look back at your prompt. That ~ sitting in it is the same shortcut: the prompt is telling you you're at home. Wander into a subfolder and watch it change to ~/Documents. Your prompt has been quietly answering pwd this whole time.

Prove It

Open a terminal, run pwd before going anywhere, and read the path it prints. That's your home directory.

Then use Select directory below and pick that exact folder. Git Gud works out where your home directory is on its own and compares the two — so this is a real answer with a right and a wrong, not a checkbox.

Run ls while you're there too, then exit so your shell saves its history, and press Verify.
