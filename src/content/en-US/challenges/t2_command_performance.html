Learn the three parts every command is made of, and how to ask a command what it can do.

Command, Arguments, Options

Every line you type at a prompt has the same shape. Once you see it, unfamiliar commands stop looking like magic spells and start looking like sentences.

command [options] [arguments]

  • The command is the verb — the program you want to run. It always comes first. ls, echo, git.
  • Arguments are what the command should act on. The noun. In cd Documents, the argument is Documents.
  • Options (also called flags or switches) change how the command behaves. They start with a dash: -a, -l, --help.

So ls -l Documents reads as: list (command), the long way (option), the Documents folder (argument). Three parts, separated by spaces.

That spacing matters more than beginners expect. ls-l is one word and the shell will tell you no such command exists. Spaces are how the shell knows where one part ends and the next begins.

Short and Long Options

Most options come in two spellings for the same thing:

  • Short, one dash and one letter: -a. Quick to type. Can usually be bundled — ls -la means -l and -a together.
  • Long, two dashes and a word: --all. Slower to type, but you can read it back in six months and know what it did.

Use the short ones when you're typing, the long ones when you're writing something down for someone else — including future you.

A Command With an Argument

echo does exactly one thing: it prints back whatever you give it.

echo hello

hello

On its own, echo with nothing after it prints an empty line — the command with no argument has nothing to say. Give it several words and it prints all of them:

echo I am talking to my computer

It looks pointless. It isn't: echo is how you check what something contains before you do anything risky with it, and it's the first thing you'll reach for when a script isn't doing what you expected.

A Command With an Option

ls lists what's in the folder you're currently standing in. Try it bare first:

ls

Now add an option and watch the same command answer differently:

ls -a

-a is short for all, and suddenly there are extra entries beginning with a dot — .bashrc, .gitconfig. A leading dot means "hidden", and hidden simply means ls skips it unless asked. There's no permission involved; they're ordinary files with an unassuming name. Git keeps its entire repository in one of them, which is a trick you'll meet later.

One more:

ls -l

-l is long — one item per line, with its size and when it last changed. Same command, same folder, a different amount of detail, because you asked for it.

And because short options bundle, this does both at once:

ls -la

Ask the Command Itself

Nobody memorises options. What experienced people actually do is ask, and almost every command answers the same question:

ls --help

Out comes a wall of text. Don't read it all — read the first few lines, which say what the command is for, then skim the list of options down the left until something looks like what you want. That's the skill: skimming, not memorising.

Try it on a command you have never used in your life:

mkdir --help

You now know what mkdir does and roughly how to drive it, without anyone telling you. That's the move that makes the terminal learnable instead of a list of things to memorise — and you'll meet mkdir properly two challenges from now.

On macOS, some commands answer man ls instead of --help — man is short for manual. Press q to get out of it.

Clearing the Clutter

After all that output the window is a mess. One command fixes it:

clear

Nothing is deleted — your history is intact and the up arrow still works. It just scrolls the noise out of the way so you can think.

When you've run echo with something to say, ls with an option, and --help on anything at all, close the terminal with exit so your shell saves its history, then press Verify.
