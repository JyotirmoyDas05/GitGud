Abra um terminal, execute seus dois primeiros comandos e aprenda a ler a linha com que ele recebe você.

O que é um Terminal

Um terminal é uma janela onde você digita instruções para o seu computador em vez de clicar nelas. Essa é toda a ideia. Tudo o que você já faz — abrir uma pasta, criar uma nova, renomear um arquivo, copiar algo — tem um equivalente digitado, e a versão digitada costuma ser mais rápida e sempre pode ser repetida.

Você vai ouvir várias palavras para mais ou menos a mesma coisa, e vale a pena desembaraçar isso uma vez:

  • O terminal é a janela. Ele mostra texto e recebe o que você digita.
  • O shell é o programa rodando dentro dele que realmente entende o que você digita. Os mais comuns são Bash, Zsh e PowerShell.
  • Linha de comando e CLI são nomes gerais para esse jeito de trabalhar.

Na prática, as pessoas usam os quatro de forma intercambiável, e nós também vamos usar. Se alguém disser para você "abrir um terminal", é dessa janela que ela está falando.

Ele parece intimidador porque está vazio e nada diz o que fazer. Mas não é perigoso. Nada neste módulo pode quebrar nada — você vai mostrar seu próprio nome de usuário e criar uma pasta de prática. Ninguém está julgando sua digitação.

Abra Seu Terminal

Windows. O Windows vem com PowerShell, mas os comandos deste módulo — e quase todo tutorial, README e resposta do Stack Overflow que você ainda vai ler — são escritos para um shell estilo Unix. O jeito mais fácil de ter um é o Git Bash, que vem de graça com Git for Windows. Instale com as opções padrão e depois abra o Git Bash pelo menu Iniciar.

Essa instalação também coloca o Git no seu computador, do qual você vai precisar mais tarde mesmo assim — um desafio mais adiante confirma que ele está configurado direitinho. Dois coelhos.

macOS. Pressione Cmd + Space, digite Terminal, pressione enter. Ele também fica em Aplicativos › Utilitários.

Linux. Normalmente Ctrl + Alt + T, ou procure por Terminal nos seus aplicativos.

Você agora deve estar vendo uma janela quase vazia com uma linha de texto e um cursor piscando. Essa linha é a próxima coisa a entender.

Lendo o Prompt

A linha que está esperando por você se chama prompt. Não é decoração — é uma barra de status, e ela está dizendo três coisas úteis antes mesmo de você digitar qualquer coisa.

jyoti@laptop ~/code $

  • jyoti — com qual usuário você está conectado.
  • laptop — com qual máquina você está falando. Isso importa mais do que você imagina quando você começar a se conectar a outros computadores.
  • ~/code — onde você está. O terminal está sempre parado em alguma pasta, e é esta. O próximo desafio depois deste é inteiramente sobre essa parte.
  • $ — "sua vez". Tudo depois dele é o que você digita.

O seu vai parecer diferente. O Zsh no macOS muitas vezes termina com % em vez de $, alguns prompts têm duas linhas, alguns são coloridos, alguns mostram a branch atual do Git. As partes mudam de lugar; a ideia não.

É também por isso que as documentações escrevem comandos com um $ na frente — é uma forma curta de dizer "digite isso no seu prompt". Você nunca digita o $ em si. As caixas de código no Git Gud também mostram ele, e o botão de copiar deixa ele de fora.

Diga Olá

Digite isso e pressione enter:

whoami

Ele mostra seu nome de usuário. É isso. Esse é o comando inteiro.

jyoti

Agora tente outro:

date

Sat Sep 20 09:24:11 IST 2026

Você agora já usou um terminal. O padrão que você acabou de conhecer — digitar uma palavra, pressionar enter, ler o que volta — é a interação inteira. Todo o resto são palavras mais interessantes.

Pressione a seta para cima. Seu shell lembra o que você digitou e vai devolver para você. Pressione algumas vezes. Esse é o maior economizador de tempo desta página.

Fechando o Terminal

Clicar no botão de fechar da janela funciona. Mas existe um jeito certo, e é um comando como qualquer outro:

exit

A janela fecha. Reabra do mesmo jeito que antes — um terminal é uma coisa barata e descartável, e você vai abrir e fechar dezenas por dia sem nem pensar nisso.

Um motivo para preferir o exit: aquela memória do que você digitou fica guardada em um arquivo, e o Bash e o Zsh só gravam esse arquivo quando o shell fecha direitinho. O que nos leva a como este desafio é verificado.

Como o Git Gud Verifica Isso

Comandos como whoami não mudam nada no seu computador, então não há pasta ou arquivo para o aplicativo olhar depois. Em vez disso, o Git Gud lê o arquivo de histórico que o seu próprio shell guarda — ~/.bash_history para o Bash, e o equivalente para Zsh, Fish e PowerShell — e procura os comandos que este desafio pediu.

Ele lê as últimas centenas de linhas, só na sua máquina, e nada é enviado para lugar nenhum. Cada verificação abaixo diz exatamente qual arquivo ela leu.

Então: execute whoami e date, depois exit para fechar o terminal para que seu shell salve o histórico, abra um novo, volte aqui e pressione Verificar.

Se a Verificação Não Enxergar Seus Comandos

O Bash e o Zsh salvam o histórico quando o shell sai, não enquanto você digita. Se você fez o trabalho mas a verificação não encontra, seu terminal quase certamente ainda está aberto. Digite exit e pressione Verificar de novo.

No Windows, o cmd.exe não guarda histórico nenhum. Use o Git Bash ou o PowerShell.
