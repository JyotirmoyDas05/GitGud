Monte uma pequena árvore de pastas pelo terminal com mkdir e touch.

Criando Coisas

Tudo até aqui foi só leitura — olhar e se mover. Dois comandos cobrem quase todo o criar:

  • mkdir — make directory. Cria uma pasta.
  • touch — cria um arquivo vazio.

Os dois criam coisas dentro do diretório onde você está parado agora, a menos que você dê para eles um caminho dizendo o contrário. É aqui que o desafio anterior se paga: se você não tem certeza de onde uma pasta nova vai parar, execute pwd primeiro.

touch tem um nome estranho porque criar arquivos é seu bico — seu propósito de verdade é atualizar a data de um arquivo, e criar um que ainda não existe foi um acidente conveniente. Todo mundo usa pelo acidente.

Crie a Pasta de Prática

Comece em casa, para não haver dúvida de onde isso vai parar:

cd ~

Agora crie uma pasta e entre nela:

mkdir gitgud-practice cd gitgud-practice

Como o cd, o mkdir não diz nada quando funciona. Confira com ls se quiser a confirmação — você deve, nas primeiras vezes.

Dê exatamente o nome gitgud-practice — a verificação procura esse nome. E repare que não há espaço nele. Espaços em nomes são permitidos, mas deixam os caminhos chatos de digitar, e é por isso que o mundo da programação usa tanto hífens.

Crie um Arquivo

Você agora deve estar dentro de gitgud-practice. Confirme se quiser:

pwd

Depois crie um arquivo vazio:

touch hello.txt ls

hello.txt

Ele existe e está vazio — zero bytes. O touch faz o recipiente; colocar algo dentro é trabalho de um editor de texto. Abra no editor que quiser e digite algo se quiser; nada aqui depende disso.

Crie uma Pasta, Depois um Arquivo Dentro Dela

Ainda em gitgud-practice:

mkdir notes

Agora — aqui está a parte útil — crie um arquivo dentro de notes sem entrar lá, dando para o touch um caminho relativo em vez de um nome puro:

touch notes/day-one.txt

Leia aquele argumento do jeito que você lê um caminho: a pasta notes, e dentro dela, um arquivo chamado day-one.txt. Comandos aceitam caminhos, não só nomes, em todo lugar. Você quase nunca precisa dar cd para algum lugar só para fazer uma coisa nele.

Confira seu trabalho:

ls notes

Digite ls no e pressione Tab. O autocompletar com tab funciona nas pastas que você acabou de criar, como em qualquer outra — e livra você do erro de digitação que senão deixaria você encarando um "No such file or directory" por um minuto.

Várias Pastas de Uma Vez

Tente criar uma pasta aninhada do jeito óbvio e veja ela recusar:

mkdir notes/archive/2026

mkdir: cannot create directory 'notes/archive/2026': No such file or directory

Justo — archive ainda não existe, e o mkdir cria um diretório, não uma corrente deles. Em vez de criar cada nível à mão, peça para ele:

mkdir -p notes/archive/2026 ls notes

-p é a forma curta de parents: cria as pastas que faltarem no caminho. Essa é aquela regra de dois desafios atrás em ação — mesmo comando, uma opção, comportamento diferente, e o mkdir --help teria contado isso para você.

Sua árvore agora está assim:

gitgud-practice/ ├── hello.txt └── notes/ ├── day-one.txt └── archive/ └── 2026/

O Que É Verificado

Duas coisas, juntas. O Git Gud lê a pasta gitgud-practice para confirmar que a árvore está realmente lá, e confere seu histórico do shell por mkdir e touch — porque qualquer um pode clicar com o botão direito e escolher Nova Pasta, e não é disso que este módulo trata.

Use Select directory abaixo para escolher sua pasta gitgud-practice, feche o terminal com exit para que o histórico seja salvo, e pressione Verificar.

Guarde a pasta quando terminar, ou apague — nada mais adiante depende dela. Você vai criar uma pasta de projeto de verdade logo, logo, com os mesmos dois comandos.

Criando Coisas

  • Criar uma pasta
    • mkdir <FOLDERNAME>
  • Criar uma corrente inteira de pastas
    • mkdir -p <A>/<B>/<C>
  • Criar um arquivo vazio
    • touch <FILENAME>
  • Criar um dentro de outra pasta
    • touch <FOLDERNAME>/<FILENAME>
  • Conferir se funcionou
    • ls <FOLDERNAME>

Esse é o módulo inteiro de terminal. Você sabe abrir um terminal, ler um prompt, executar um comando com opções e argumentos, descobrir onde está, ir para outro lugar e criar coisas quando chegar lá. Tudo que o Git pedir de você daqui em diante são esses mesmos movimentos com palavras diferentes.
