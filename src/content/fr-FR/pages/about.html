Git Gud enseigne les commandes Git du quotidien que les développeurs utilisent réellement, ainsi que le GitHub Flow — la façon dont les gens collaborent sur GitHub. Il commence plus tôt que la plupart des tutoriels : les cinq premiers défis portent sur le terminal lui-même, car « ouvrez un terminal et exécutez git init » n'est pas une seule instruction si vous n'avez jamais ouvert de terminal.

Certains défis nécessitent une connexion internet, vous devrez donc être en ligne pour les terminer. Vous pouvez toujours ouvrir l'application et lire les défis et les ressources hors ligne.

Un véritable environnement de développement

Git Gud utilise le vrai terminal, le vrai Git et le vrai GitHub plutôt que de les émuler. Quand vous aurez terminé, vous aurez de véritables dépôts sur votre compte GitHub et des carrés verts sur votre graphique de contributions. Rien ici n'est une simulation, c'est aussi pourquoi chaque défi est vérifié en exécutant Git sur vos propres dépôts — si un défi est réussi, c'est qu'il a réellement fonctionné.

Ce dont vous avez besoin

Rien, pour commencer — le module sur le terminal utilise ce que votre ordinateur possède déjà. Ensuite, Git et un compte GitHub, que deux des défis vous aident à mettre en place. Vous n'avez pas besoin de Node.js, de Python ni d'aucun autre environnement d'exécution — Git Gud est distribué sous la forme d'une seule application native.

À propos des défis sur le terminal

Des commandes comme pwd et ls ne modifient rien sur votre ordinateur, il n'y a donc aucun fichier à inspecter ensuite pour vérifier que vous les avez exécutées. Ces défis sont vérifiés en lisant le fichier d'historique que votre propre shell conserve — ~/.bash_history et ses équivalents pour Zsh, Fish et PowerShell. Seules les quelques centaines de lignes les plus récentes sont lues, tout se passe entièrement sur votre machine, rien n'est envoyé ailleurs, et chaque vérification nomme le fichier qu'elle a lu.

Comment c'est construit

Git Gud est une application Tauri : un backend Rust qui exécute Git et communique avec GitHub, et une interface React affichée par la vue web native du système d'exploitation. Il n'y a pas de moteur de navigateur intégré, c'est pourquoi le téléchargement se mesure en mégaoctets plutôt qu'en centaines de mégaoctets.

Le dépôt compagnon que vous forkez pendant les défis est git-gud-verifywork. Son automatisation s'exécute entièrement sur GitHub Actions — il n'y a aucun serveur qui puisse tomber en panne.

Crédit à qui de droit

Git Gud est un portage de Git-it, une application Electron écrite par @jlord et de nombreux contributeurs, publiée sous la licence BSD 2-Clause. La structure des défis et une grande partie des textes sont les leurs. Cette version reconstruit l'application sur Tauri, remplace le service de vérification retiré par GitHub Actions, et corrige un certain nombre de vérifications qui avaient cessé de fonctionner à mesure que Git et GitHub évoluaient.

La conception de l'interface emprunte son système de tokens à T3 Code, utilisé sous la licence MIT.
