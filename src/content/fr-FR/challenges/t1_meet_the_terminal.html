Ouvrez un terminal, exécutez vos deux premières commandes et apprenez à lire la ligne qui vous accueille.

Ce qu'est un terminal

Un terminal est une fenêtre où vous tapez des instructions à votre ordinateur au lieu de les cliquer. C'est toute l'idée. Tout ce que vous faites déjà — ouvrir un dossier, en créer un nouveau, renommer un fichier, copier quelque chose — a un équivalent tapé au clavier, et la version tapée est généralement plus rapide et toujours reproductible.

Vous entendrez plusieurs mots pour à peu près la même chose, et cela vaut la peine de les démêler une fois :

  • Le terminal est la fenêtre. Elle affiche du texte et reçoit vos frappes au clavier.
  • Le shell est le programme qui tourne à l'intérieur et qui comprend réellement ce que vous tapez. Les plus courants sont Bash, Zsh et PowerShell.
  • Ligne de commande et CLI sont des noms généraux pour cette façon de travailler.

En pratique, on utilise les quatre de façon interchangeable, et nous ferons de même. Si quelqu'un vous dit d'« ouvrir un terminal », il parle de cette fenêtre.

Elle semble intimidante parce qu'elle est vide et que rien ne vous dit quoi faire. Elle n'est pas dangereuse. Rien dans ce module ne peut rien casser — vous allez afficher votre propre nom d'utilisateur et créer un dossier d'entraînement. Personne ne juge votre frappe.

Ouvrez votre terminal

Windows. Windows est livré avec PowerShell, mais les commandes de ce module — et de presque tous les tutoriels, README et réponses Stack Overflow que vous lirez un jour — sont écrites pour un shell de style Unix. Le moyen le plus simple d'en obtenir un est Git Bash, fourni gratuitement avec Git pour Windows. Installez-le avec les options par défaut, puis ouvrez Git Bash depuis le menu Démarrer.

Cette installation met aussi Git sur votre ordinateur, dont vous aurez besoin plus tard de toute façon — un défi plus loin vérifie qu'il est bien configuré. Deux en un.

macOS. Appuyez sur Cmd + Space, tapez Terminal, appuyez sur entrée. Il se trouve aussi dans Applications › Utilitaires.

Linux. Généralement Ctrl + Alt + T, ou cherchez Terminal dans vos applications.

Vous devriez maintenant voir une fenêtre presque vide avec une ligne de texte et un curseur clignotant. Cette ligne est la prochaine chose à comprendre.

Lire l'invite

La ligne qui vous attend s'appelle l'invite (le prompt). Ce n'est pas de la décoration — c'est une barre d'état, et elle vous dit trois choses utiles avant même que vous tapiez quoi que ce soit.

jyoti@laptop ~/code $

  • jyoti — l'utilisateur sous lequel vous êtes connecté.
  • laptop — la machine à laquelle vous parlez. Cela compte plus qu'on ne le croit dès que vous commencez à vous connecter à d'autres ordinateurs.
  • ~/code — où vous êtes. Le terminal se tient toujours dans un dossier, et c'est celui-ci. Le prochain défi après celui-ci est entièrement consacré à cette partie.
  • $ — « à vous ». Tout ce qui suit est ce que vous tapez.

La vôtre sera différente. Zsh sur macOS se termine souvent par % au lieu de $, certaines invites tiennent sur deux lignes, certaines sont en couleur, certaines affichent la branche Git actuelle. Les éléments se déplacent ; l'idée, non.

C'est aussi pour cela que la documentation écrit les commandes avec un $ devant — c'est un raccourci pour « tapez ceci à votre invite ». Vous ne tapez jamais le $ lui-même. Les blocs de code de Git Gud l'affichent aussi, et le bouton copier l'exclut.

Dites bonjour

Tapez ceci et appuyez sur entrée :

whoami

Elle affiche votre nom d'utilisateur. C'est tout. C'est toute la commande.

jyoti

Essayez-en maintenant une autre :

date

Sat Sep 20 09:24:11 IST 2026

Vous venez d'utiliser un terminal. Le schéma que vous venez de rencontrer — taper un mot, appuyer sur entrée, lire ce qui revient — est toute l'interaction. Tout le reste, ce sont des mots plus intéressants.

Appuyez sur la flèche du haut. Votre shell se souvient de ce que vous avez tapé et vous le rendra. Appuyez plusieurs fois. C'est le plus grand gain de temps de cette page.

Fermer le terminal

Cliquer sur le bouton de fermeture de la fenêtre fonctionne. Mais il existe une méthode propre, et c'est une commande comme les autres :

exit

La fenêtre se ferme. Rouvrez-la comme avant — un terminal est un objet jetable et sans coût, et vous en ouvrirez et fermerez des dizaines par jour sans y penser.

Une raison de préférer exit : cette mémoire de ce que vous avez tapé vit dans un fichier, et Bash comme Zsh ne l'écrivent que lorsque le shell se ferme correctement. Ce qui nous amène à la façon dont ce défi est vérifié.

Comment Git Gud vérifie ceci

Des commandes comme whoami ne changent rien sur votre ordinateur, il n'y a donc aucun dossier ni fichier à examiner après coup. À la place, Git Gud lit le fichier d'historique que votre propre shell conserve — ~/.bash_history pour Bash, et l'équivalent pour Zsh, Fish et PowerShell — et y cherche les commandes demandées par ce défi.

Il lit les quelques centaines de dernières lignes, uniquement sur votre machine, et rien n'est envoyé ailleurs. Chaque vérification ci-dessous nomme le fichier exact qu'elle a lu.

Donc : exécutez whoami et date, puis exit pour fermer le terminal afin que votre shell enregistre son historique, ouvrez-en un nouveau, revenez ici et appuyez sur Vérifier.

Si la vérification ne voit pas vos commandes

Bash et Zsh enregistrent leur historique quand le shell se termine, pas au fur et à mesure de la frappe. Si vous avez fait le travail mais que la vérification ne le trouve pas, votre terminal est presque certainement encore ouvert. Tapez exit et appuyez à nouveau sur Vérifier.

Sur Windows, cmd.exe ne conserve aucun historique. Utilisez Git Bash ou PowerShell.
