Abre una terminal, ejecuta tus dos primeros comandos y aprende a leer la línea con la que te recibe.

Qué es una terminal

Una terminal es una ventana donde escribes instrucciones para tu ordenador en lugar de hacer clic en ellas. Esa es toda la idea. Todo lo que ya haces — abrir una carpeta, crear una nueva, renombrar un archivo, copiar algo — tiene un equivalente escrito, y la versión escrita suele ser más rápida y siempre repetible.

Escucharás varias palabras para más o menos lo mismo, y merece la pena aclararlas una vez:

  • La terminal es la ventana. Dibuja texto y recibe lo que escribes.
  • El shell es el programa que se ejecuta dentro y que realmente entiende lo que escribes. Los más comunes son Bash, Zsh y PowerShell.
  • Línea de comandos y CLI son nombres generales para esta forma de trabajar.

En la práctica se usan los cuatro de forma intercambiable, y así lo haremos aquí. Si alguien te dice que «abras una terminal», se refiere a esta ventana.

Parece intimidante porque está vacía y nada te dice qué hacer. No es peligrosa. Nada en este módulo puede romper nada — mostrarás tu propio nombre de usuario y crearás una carpeta de práctica. Nadie está juzgando cómo escribes.

Abre tu terminal

Windows. Windows incluye PowerShell, pero los comandos de este módulo — y casi todos los tutoriales, README y respuestas de Stack Overflow que leerás — están escritos para un shell de estilo Unix. La forma más fácil de conseguir uno es Git Bash, que viene gratis con Git para Windows. Instálalo con las opciones predeterminadas, luego abre Git Bash desde el menú Inicio.

Esa instalación también pone Git en tu ordenador, que necesitarás más adelante de todos modos — un reto más adelante confirma que está bien configurado. Dos pájaros de un tiro.

macOS. Pulsa Cmd + Space, escribe Terminal, pulsa intro. También está en Aplicaciones › Utilidades.

Linux. Normalmente Ctrl + Alt + T, o busca en tus aplicaciones Terminal.

Ahora deberías ver una ventana casi vacía con una línea de texto y un cursor parpadeante. Esa línea es lo siguiente que debes entender.

Cómo leer el prompt

La línea que te espera se llama prompt. No es decoración — es una barra de estado, y te está diciendo tres cosas útiles antes de que escribas nada.

jyoti@laptop ~/code $

  • jyoti — con qué usuario has iniciado sesión.
  • laptop — con qué máquina estás hablando. Esto importa más de lo que parece cuando empieces a conectarte a otros ordenadores.
  • ~/code — dónde estás. La terminal siempre está situada en alguna carpeta, y es esta. El reto que viene después del siguiente trata enteramente de esta parte.
  • $ — «tu turno». Todo lo que va después es lo que escribes.

La tuya será diferente. Zsh en macOS suele terminar con % en lugar de $, algunos prompts ocupan dos líneas, algunos tienen colores, algunos muestran la rama actual de Git. Las partes cambian de lugar; la idea no.

Por eso la documentación escribe los comandos con un $ delante — es una forma corta de decir «escribe esto en tu prompt». Nunca escribes el $. Los recuadros de código en Git Gud también lo muestran, y el botón de copiar lo omite.

Di hola

Escribe esto y pulsa intro:

whoami

Muestra tu nombre de usuario. Eso es todo. Ese es todo el comando.

jyoti

Ahora prueba otro:

date

Sat Sep 20 09:24:11 IST 2026

Ya has usado una terminal. El patrón que acabas de ver — escribe una palabra, pulsa intro, lee lo que devuelve — es toda la interacción. Todo lo demás son palabras más interesantes.

Pulsa la flecha hacia arriba. Tu shell recuerda lo que escribiste y te lo devolverá. Púlsala varias veces. Este es el mayor ahorro de tiempo de esta página.

Cómo cerrar la terminal

Hacer clic en el botón de cerrar de la ventana funciona. Pero hay una forma correcta, y es un comando como cualquier otro:

exit

La ventana se cierra. Vuelve a abrirla igual que antes — una terminal es algo barato y desechable, y abrirás y cerrarás docenas al día sin pensarlo.

Una razón para preferir exit: ese recuerdo de lo que escribiste vive en un archivo, y Bash y Zsh solo lo escriben cuando el shell se cierra correctamente. Lo que nos lleva a cómo se comprueba este reto.

Cómo comprueba esto Git Gud

Comandos como whoami no cambian nada en tu ordenador, así que no hay ninguna carpeta o archivo que la aplicación pueda revisar después. En su lugar, Git Gud lee el archivo de historial que guarda tu propio shell — ~/.bash_history para Bash, y el equivalente para Zsh, Fish y PowerShell — y busca los comandos que pide este reto.

Lee solo las últimas cien líneas, solo en tu máquina, y nada se envía a ningún sitio. Cada comprobación indica el archivo exacto que leyó.

Así que: ejecuta whoami y date, luego exit para cerrar la terminal y que tu shell guarde su historial, abre una nueva y vuelve aquí y pulsa Verificar.

Si la comprobación no ve tus comandos

Bash y Zsh guardan su historial cuando el shell termina, no mientras escribes. Si hiciste el trabajo pero la comprobación no lo encuentra, es casi seguro que tu terminal sigue abierta. Escribe exit y pulsa Verificar de nuevo.

En Windows, cmd.exe no guarda ningún historial. Usa Git Bash o PowerShell.
