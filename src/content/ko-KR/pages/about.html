Git Gud에서는 개발자가 실제로 사용하는 일상적인 Git 명령어와, GitHub에서 협업하는 방식인 GitHub Flow를 배웁니다. 대부분의 튜토리얼보다 이른 단계부터 시작합니다. 처음 다섯 개의 챌린지는 터미널 자체에 대한 내용입니다. 왜냐하면, 터미널을 열어본 적이 없는 분에게는 "터미널을 열고 git init을 실행하세요"가 하나의 안내가 아니기 때문입니다.

일부 챌린지는 인터넷 연결이 필요하므로, 끝까지 마치시려면 온라인 상태에서 이용해 주세요. 앱을 열고 챌린지와 리소스를 읽는 것은 언제나 오프라인으로 하실 수 있습니다.

실제 개발 환경

Git Gud은 에뮬레이션이 아니라 실제 터미널, 실제 Git, 실제 GitHub를 사용합니다. 과정을 마치면 GitHub 계정에 실제 리포지토리가 생기고 기여 차트에 초록색 칸이 표시됩니다. 여기에는 시뮬레이션이 전혀 없습니다. 그래서 각 챌린지는 여러분의 리포지토리에 대해 Git을 실행해서 확인합니다. 챌린지를 통과했다면, 정말로 동작한 것입니다.

필요한 준비물

처음에는 아무것도 필요 없습니다. 터미널 모듈은 컴퓨터에 이미 있는 것을 사용합니다. 그 다음에는 Git과 GitHub 계정이 필요한데, 두 개의 챌린지에서 절차를 안내해 드립니다. Node.js나 Python 등 다른 런타임은 필요하지 않습니다. Git Gud은 단일 네이티브 애플리케이션으로 제공됩니다.

터미널 챌린지에 대하여

pwd나 ls 같은 명령어는 컴퓨터에서 아무것도 변경하지 않으므로, 실행했는지 나중에 확인할 수 있는 파일이 없습니다. 해당 챌린지들은 여러분의 셸이 보관하는 히스토리 파일을 읽어서 확인합니다. ~/.bash_history 및 Zsh, Fish, PowerShell의 동등한 파일입니다. 최근 수백 줄만 읽고, 모든 과정은 여러분의 컴퓨터에서만 이루어지며, 어디에도 전송되지 않습니다. 각 검사에서는 읽은 파일 이름을 표시합니다.

만들어진 방식

Git Gud은 Tauri 애플리케이션입니다. Git을 실행하고 GitHub와 통신하는 Rust 백엔드와, 운영체제 자체의 웹 뷰로 렌더링되는 React 인터페이스로 이루어져 있습니다. 번들된 브라우저 엔진이 없어서, 다운로드 용량은 수백 메가바이트가 아니라 수 메가바이트입니다.

챌린지 중에 포크하는 동반 리포지토리는 git-gud-verifywork입니다. 자동화는 전부 GitHub Actions에서 실행됩니다. 중단될 서버가 없습니다.

기여해 주신 분들

Git Gud은 Git-it의 포팅 버전입니다. @jlord와 많은 기여자가 작성한 Electron 앱으로, BSD 2-Clause 라이선스로 공개되어 있습니다. 챌린지 구조와 글의 상당 부분은 원작자의 것입니다. 이 버전은 애플리케이션을 Tauri로 다시 만들고, 종료된 검증 서비스를 GitHub Actions로 교체했으며, Git과 GitHub의 변경으로 동작하지 않게 된 많은 검사를 수정했습니다.

인터페이스 디자인은 T3 Code의 토큰 시스템을 참고했습니다. MIT 라이선스로 이용됩니다.
