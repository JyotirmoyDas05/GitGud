mkdir과 touch로 터미널에서 작은 폴더 트리를 만드세요.

만들기

지금까지는 읽기 전용이었습니다 — 보고 옮겼을 뿐입니다. 만들기는 두 명령으로 거의 다 됩니다:

  • mkdir — make directory의 뜻. 폴더를 만듭니다.
  • touch — 빈 파일을 만듭니다.

둘 다, 다른 길을 말하는 경로를 주지 않는 한 지금 서 있는 디렉터리 안에 만듭니다. 여기서 지난 챌린지가 빛을 발합니다: 새 폴더가 어디에 생길지 불안하면 먼저 pwd를 실행하세요.

touch라는 이상한 이름은 파일 만들기가 본업이 아니기 때문입니다 — 본래 목적은 파일의 시간 정보를 고치는 것이며, 아직 없는 것을 만드는 것은 덤으로 생긴 일입니다. 모두가 그 덤 때문에 씁니다.

연습용 폴더 만들기

만드는 장소에 의문이 없도록 집에서 시작합니다:

cd ~

폴더를 만들고 안으로 들어가세요:

mkdir gitgud-practice cd gitgud-practice

cd와 마찬가지로 mkdir은 제대로 돼도 아무 말이 없습니다. 안심하고 싶으면 ls로 확인하세요 — 처음 몇 번은 그래야 합니다.

이름은 반드시 gitgud-practice로 하세요 — 확인은 그 이름을 찾습니다. 공백이 없다는 점에도 주목하세요. 이름의 공백은 허용되지만 입력하기 어려워지므로 프로그래밍 세계에서는 하이픈을 즐겨 씁니다.

파일 만들기

지금 있는 곳은 gitgud-practice 안이어야 합니다. 좋다면 확인하세요:

pwd

다음에 빈 파일을 만드세요:

touch hello.txt ls

hello.txt

존재하며 속은 비어 있습니다 — 0바이트입니다. touch는 그릇을 만듭니다. 안에 뭔가 넣는 것은 텍스트 편집기의 일입니다. 좋다면 좋아하는 편집기로 열어 뭔가 입력하세요. 여기서는 아무것에도 의존하지 않습니다.

폴더를 만들고 그 안에 파일 만들기

아직 gitgud-practice 안에 있습니다:

mkdir notes

여기가 쓸모 있는 대목입니다 — notes 안에 안으로 들어가지 않고 파일을 만듭니다. 그냥 이름이 아니라 상대 경로를 touch에 넘기세요:

touch notes/day-one.txt

그 인자는 경로로 읽으세요: 폴더 notes 안의 day-one.txt라는 파일. 명령은 어디서든 이름뿐 아니라 경로를 받습니다. 한 가지 일을 위해 굳이 cd할 필요는 거의 없습니다.

작업을 확인하세요:

ls notes

ls no까지 입력하고 Tab을 누르세요. 탭 완성은 방금 만든 폴더에도 다른 것과 똑같이 통합니다 — 덕분에 오타를 막을 수 있습니다. 오타가 없으면 "No such file or directory"를 보며 1분 고민하지 않아도 됩니다.

여러 폴더 한 번에

중첩 폴더를 당연한 방법으로 만들려다 거부당하는 모습을 보세요:

mkdir notes/archive/2026

mkdir: cannot create directory 'notes/archive/2026': No such file or directory

당연합니다 — archive는 아직 없고, mkdir은 줄줄이가 아니라 하나의 디렉터리를 만듭니다. 각 단계를 손으로 만드는 대신 이렇게 부탁하세요:

mkdir -p notes/archive/2026 ls notes

-p는 parents의 줄임말입니다: 중간에 빠진 폴더도 만듭니다. 이것은 두 챌린지 전의 규칙이 동작하는 모습입니다 — 같은 명령에 하나의 옵션으로 동작이 바뀌며, mkdir --help가 알려주었을 것입니다.

트리는 지금 이렇게 돼 있습니다:

gitgud-practice/ ├── hello.txt └── notes/ ├── day-one.txt └── archive/ └── 2026/

확인 내용

두 가지를 합친 내용입니다. Git Gud는 gitgud-practice 폴더를 읽어 트리가 정말 있는지 확인하고, 그리고 셸 히스토리에서 mkdir과 touch를 확인합니다 — 오른쪽 클릭 새로 만들기로도 만들 수 있으며, 이 모듈의 취지가 아니기 때문입니다.

아래 Select directory로 자신의 gitgud-practice 폴더를 고르고, 히스토리 저장을 위해 exit로 터미널을 닫고 Verify를 누르세요.

끝나면 폴더는 남겨도 지워도 됩니다 — 뒤에는 아무것에도 의존하지 않습니다. 같은 두 명령으로 곧 진짜 프로젝트 폴더를 만들게 됩니다.

만들기

  • 폴더 만들기
    • mkdir <FOLDERNAME>
  • 폴더 사슬 한 번에 만들기
    • mkdir -p <A>/<B>/<C>
  • 빈 파일 만들기
    • touch <FILENAME>
  • 다른 폴더 안에 만들기
    • touch <FOLDERNAME>/<FILENAME>
  • 제대로 됐는지 확인하기
    • ls <FOLDERNAME>

터미널 모듈은 이상입니다. 터미널을 열고, 프롬프트를 읽고, 옵션과 인자를 붙여 명령을 실행하고, 지금 어디인지 알아내고, 다른 곳으로 가고, 도착해서 만들 수 있습니다. 앞으로 Git이 요구하는 것은 말만 다를 뿐 같은 움직임입니다.
