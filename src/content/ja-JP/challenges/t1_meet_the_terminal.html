ターミナルを開き、最初の2つのコマンドを実行して、最初に表示される行の読み方を学びましょう。

ターミナルとは

ターミナルとは、クリックの代わりにコンピュータへの指示を入力するためのウィンドウです。考え方はそれだけです。普段行っている操作——フォルダを開く、新規作成する、ファイル名を変更する、コピーする——にはすべて入力による同等の操作があり、入力版の方が速く、必ず再現できます。

ほぼ同じものを指すいくつかの言葉を耳にするはずなので、最初に一度だけ整理しておきます:

  • ターミナルはウィンドウそのものです。テキストを描画し、キー入力を受け取ります。
  • シェルはその中で実際に動作し、入力内容を理解するプログラムです。代表的なものに Bash、Zsh、PowerShell があります。
  • コマンドラインや CLI は、この作業方式の一般的な呼び名です。

実際には4つとも同じ意味で使われますし、この教材でもそうします。「ターミナルを開いて」と言われたら、このウィンドウのことだと思ってください。

空っぽで何をすればいいのか教えてくれないため、威圧的に見えますが、危険ではありません。このモジュールで壊れるものは何もありません——自分のユーザー名を表示して、練習用フォルダを作るだけです。タイピングを誰かに評価されることもありません。

ターミナルを開く

Windows。 WindowsにはPowerShellが付属していますが、このモジュールのコマンド——そして今後読むほぼすべてのチュートリアル、README、Stack Overflowの回答——はUnix風シェル向けに書かれています。最も簡単な入手方法は Git Bash で、Git for Windows に無料で付属しています。既定のオプションでインストールし、スタートメニューから Git Bash を開いてください。

このインストールで後で必要になるGitも一緒に入ります——後のチャレンジで正しく設定されたか確認します。一石二鳥です。

macOS。 Cmd + Space を押して Terminal と入力し、enterを押します。アプリケーション › ユーティリティにもあります。

Linux。 通常は Ctrl + Alt + T か、アプリケーションから Terminal を検索します。

1行のテキストと点滅するカーソルがある、ほぼ空のウィンドウが表示されるはずです。その行が次に理解すべきものです。

プロンプトを読む

待機している行は プロンプト と呼ばれます。飾りではなくステータスバーであり、何も入力する前から3つの役立つ情報を伝えています。

jyoti@laptop ~/code $

  • jyoti — 誰としてサインインしているか。
  • laptop — どのマシンと話しているか。他のコンピュータに接続するようになると、思った以上に重要になります。
  • ~/code — 今いる場所。ターミナルは常にどこかのフォルダの中に立っており、それがこの場所です。次の次のチャレンジは丸ごとこの部分についてです。
  • $ —「あなたの番です」という意味です。これより後が入力する部分です。

皆さんのものは見た目が違うはずです。macOSのZshは % で終わることが多く( $ ではなく)、2行のプロンプト、カラフルなもの、現在のGitブランチを表示するものもあります。配置は変わりますが、考え方は同じです。

ドキュメントがコマンドの前に $ を付けて書くのもこのためです——「プロンプトでこれを入力して」という略記です。 $ 自体を入力することはありません。Git Gudのコードボックスにも表示されますが、コピーボタンでは除外されます。

あいさつしてみる

以下を入力してenterを押してください:

whoami

ユーザー名が表示されます。それだけです。それがこのコマンドのすべてです。

jyoti

もう1つ試してみましょう:

date

Sat Sep 20 09:24:11 IST 2026

これでターミナルを使えました。今体験したパターン——単語を入力し、enterを押して、返ってきたものを読む——が対話のすべてです。後はもっと面白い単語が増えるだけです。

上矢印を押してください。シェルは入力内容を記憶していて、呼び戻してくれます。何度か押してみてください。このページで最も時間を節約できる技です。

ターミナルを閉じる

ウィンドウの閉じるボタンを押しても閉じられます。ただ正式な方法があり、それも他のコマンドと同じコマンドです:

exit

ウィンドウが閉じます。先ほどと同じ方法で開き直してください——ターミナルは安価で使い捨てのものであり、1日に何十回も何も考えずに開閉するようになります。

exit を使う理由の1つ: 入力の記憶はファイルに保存され、BashやZshはシェルが正しく閉じたときにだけ書き出します。このチャレンジのチェック方法に関係してきます。

Git Gudのチェック方法

whoami のようなコマンドは何も変更しないため、後から確認できるフォルダやファイルが残りません。代わりにGit Gudは、シェル自身が保持する履歴ファイル——Bashなら ~/.bash_history、Zsh、Fish、PowerShellなら相当するもの——を読み、このチャレンジで求めたコマンドを探します。

最後の数百行だけを皆さんのマシン上でのみ読み取り、どこにも送信しません。各チェックでは読み取った正確なファイル名を示します。

手順: whoami と date を実行し、履歴を保存するために exit でターミナルを閉じ、新しいものを開いて、ここに戻ってVerifyを押してください。

コマンドが見えない場合

BashとZshは入力中ではなくシェルが終了するときに履歴を保存します。作業したのにチェックで見つからない場合、ほぼ確実にターミナルがまだ開いています。 exit と入力して、もう一度Verifyを押してください。

Windowsでは cmd.exe は履歴を一切残しません。Git BashかPowerShellを使ってください。
