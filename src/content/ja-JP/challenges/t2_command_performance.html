すべてのコマンドに共通する3つの部品と、コマンド自身に使い方を尋ねる方法を学びましょう。

コマンド、引数、オプション

プロンプトに入力する1行はすべて同じ形をしています。一度見抜けば、見慣れないコマンドが魔法の呪文ではなく文に見えるようになります。

command [options] [arguments]

  • コマンドは動詞——実行したいプログラムです。常に最初に来ます。ls、echo、git などです。
  • 引数はコマンドの対象です。名詞にあたります。cd Documents では、引数は Documents です。
  • オプション(フラグやスイッチとも呼びます)はコマンドの動作を変える方法です。ダッシュで始まります: -a、-l、--help などです。

つまり ls -l Documents は、一覧表示して(コマンド)、詳しく(オプション)、Documentsフォルダを(引数)と読みます。3つの部品がスペースで区切られています。

この間隔は初心者が思う以上に重要です。 ls-l は1つの単語であり、シェルはそのようなコマンドはないと言います。どこで1つの部品が終わり次が始まるかを、シェルはスペースで判断しています。

短いオプションと長いオプション

ほとんどのオプションには同じ意味の2つの書き方があります:

  • 短いものはダッシュ1つと1文字です: -a。入力が速いです。通常はまとめられます—— ls -la は -l と -a を合わせた意味です。
  • 長いものはダッシュ2つと単語です: --all。入力は遅いですが、半年後に読み返しても何をしたか分かります。

入力するときは短いもの、誰かのために書き残すとき——未来の自分も含めて——は長いものを使いましょう。

引数付きのコマンド

echo は1つのことだけをします: 渡されたものをそのまま表示します。

echo hello

hello

単独の echo は何も付けないと空行を表示します——引数なしのコマンドには言うことがありません。複数の単語を渡すとすべて表示します:

echo I am talking to my computer

無意味に見えますが、そうではありません: echo は危険な操作の前に中身を確認する方法であり、スクリプトが思った通りに動かないときに最初に使うものです。

オプション付きのコマンド

ls は今立っているフォルダの中身を一覧表示します。まず何も付けずに試してください:

ls

次にオプションを付けて、同じコマンドがどう答えを変えるか見てみましょう:

ls -a

-a は all の略で、突然ドットで始まる項目が増えます—— .bashrc、.gitconfig などです。先頭のドットは「隠し」という意味で、隠しとは単に ls が頼まれない限り飛ばすということです。権限は関係なく、控えめな名前の普通のファイルです。Gitはリポジトリ全体をそのような1つに保存しており、後で出会います。

もう1つ:

ls -l

-l は long の意味——1行に1項目ずつ、サイズと最終更新日時付きで表示します。同じコマンド、同じフォルダでも、頼み方で詳しさが変わります。

短いオプションはまとめられるので、これは両方を同時に行います:

ls -la

コマンド自身に尋ねる

オプションを暗記する人はいません。経験者が実際にやるのは尋ねることであり、ほぼすべてのコマンドが同じ質問に答えてくれます:

ls --help

大量のテキストが出てきます。全部読まず、最初数行だけ読んでコマンドの目的を掴み、左側のオプション一覧から欲しいものに似たものを探します。その技術は流し読みであり、暗記ではありません。

使ったことのないコマンドで試してみましょう:

mkdir --help

誰に教わらなくても、 mkdir が何をするか、おおよその使い方が分かりました。ターミナルを暗記物ではなく学べるものにするのはこの動きです——そして mkdir には2つ後のチャレンジで正式に出会います。

macOSでは一部のコマンドが man ls で答えます( --help ではなく)—— man は manual の略です。抜けるには q を押します。

散らかった画面を片付ける

これだけ出力すると画面はぐちゃぐちゃです。1つのコマンドで直ります:

clear

何も削除されません——履歴は残り、上矢印も使えます。考えるために邪魔な出力をどかすだけです。

echo で何か表示し、 ls にオプションを付け、何かに --help を使ったら、履歴保存のために exit でターミナルを閉じてVerifyを押してください。
