Git Gudでは、開発者が実際に使う日常的なGitコマンドと、 GitHubでのコラボレーション方法であるGitHub Flowを学びます。ほとんどの チュートリアルよりも早い段階から始めます。最初の5つのチャレンジはターミナル自体についてのものです。なぜなら、 「ターミナルを開いてgit initを実行してください」は、ターミナルを開いたことがない方にとって 一つの指示ではないからです。

一部のチャレンジにはインターネット接続が必要ですので、最後まで進めるにはオンラインでご利用ください。 アプリを開いてチャレンジやリソースを読むだけなら、いつでもオフラインでご利用いただけます。

実際の開発環境

Git Gudは、エミュレーションではなく、実際のターミナル、実際のGit、実際のGitHubを使用します。終了する頃には、GitHubアカウント上に実際のリポジトリがあり、 コントリビューションチャートに緑のマスが付きます。ここにはシミュレーションは何もありません。そのため、 各チャレンジはご自身のリポジトリに対してGitを実行して確認します。チャレンジに 合格したら、それは本当に成功したということです。

必要なもの

最初は何も必要ありません。ターミナルのモジュールはお使いのコンピューターにすでにあるものを使います。 その後はGitとGitHubアカウントが必要ですが、そのうち2つのチャレンジで手順を案内します。 Node.jsやPython、その他のランタイムは必要ありません。Git Gudは 単一のネイティブアプリケーションとして提供されます。

ターミナルチャレンジについて

pwdやlsのようなコマンドはコンピューター上の何も変更しないため、 実行したかどうかを後から確認できるファイルはありません。これらのチャレンジは、 ご自身のシェルが保持する履歴ファイルを読み取って確認します。~/.bash_history やZsh、Fish、PowerShellの同等のファイルです。読み取るのは直近の数百行のみで、 すべてお使いのマシン上で行われ、何もどこにも送信されません。各チェックでは 読み取ったファイル名を表示します。

仕組み

Git GudはTauriアプリケーションです。Gitを実行してGitHubと通信するRust製の バックエンドと、OS標準のウェブビューで表示されるReact製のインターフェースで構成されています。バンドルされたブラウザエンジンはないため、 ダウンロードサイズは数百メガバイトではなく数メガバイトです。

チャレンジ中にフォークするコンパニオンリポジトリは git-gud-verifyworkです。 その自動化はすべてGitHub Actions上で動作します。ダウンするサーバーはありません。

クレジット

Git Gudは、Git-itの移植版です。 @jlordと 多くの貢献者によって書かれたElectronアプリで、 BSD 2-Clauseライセンスで公開されています。チャレンジ構成や文章の多くはオリジナルのものです。このバージョンはアプリケーションをTauriで再構築し、 廃止された検証サービスをGitHub Actionsに置き換え、GitとGitHubの変更で 動作しなくなっていた多くのチェックを修正しています。

インターフェースデザインは、 T3 Codeのトークンシステムを参考にしています。MIT ライセンスで利用されています。
